# `apps/mobile` — Capacitor hybrid mobile wrapper

A **Capacitor** wrapper around the micro-frontend shell. It packages the shell's
production web build into native **Android** and **iOS** apps, and exposes
native capabilities (camera) through the **bridge adapter** (`@shared/bridge`)
so the same web code runs in the WebView and in a plain browser.

This is Phase 5 of `plan.md`: *"Capacitor over Cordova: single web build in
`web/`, native plugins for device features, and a bridge adapter that isolates
native calls from web code (with Web-API fallback in the browser)."*

## Layout

| Path | Purpose |
| --- | --- |
| `capacitor.config.ts` | Capacitor config: `appId: com.microfrontend.shell`, `appName: MicroFrontend`, `webDir: 'web'`, `server.androidScheme: 'https'`, `plugins.Camera.direction: 'REAR'`. |
| `package.json` | `@microfrontend/mobile` (private). Deps: `@capacitor/core`/`android`/`ios` **8.5.0**, `@capacitor/camera` **8.2.3**; devDep `@capacitor/cli` **8.5.0**. |
| `project.json` | Nx project `mobile` with targets: `sync`, `build-web`, `build-android`, `build-ios`, `open-android`, `open-ios`. |
| `tsconfig.json` | Extends `../../tsconfig.base.json`; includes `capacitor.config.ts`. |
| `web/` | **Synced** shell web build (gitignored). Capacitor's `webDir`. |
| `android/` | **Generated** native Android project (gitignored). |
| `ios/` | **Generated** native iOS project (gitignored). |
| `../../scripts/sync-mobile-web.mjs` | Copies `dist/apps/shell/browser` → `apps/mobile/web` and creates `index.html` from `index.csr.html`. |

> `web/`, `android/`, and `ios/` are **gitignored** (see root `.gitignore`).
> They are build artifacts, regenerated by `cap add` / `cap sync`.

## How it works

1. **Build the shell** (`nx build shell`) → Angular SSR emits the static client
   bundle to `dist/apps/shell/browser/`.
2. **Sync to `web/`** (`scripts/sync-mobile-web.mjs`) → copies the build output
   into `apps/mobile/web/` (the Capacitor `webDir`).
3. **`cap sync`** → copies `web/` into the native projects
   (`android/app/src/main/assets/public`, `ios/App/App/public`).
4. **`cap build android` / `cap build ios`** → produces the native app
   (APK / IPA) using the Android SDK / Xcode.

### Gotcha: `index.csr.html` → `index.html`

The shell is built in **SSR mode** (`outputMode: 'server'`), so Angular emits
the client-side entry as **`index.csr.html`**, not `index.html`. Capacitor and
the WebView expect `index.html`. `scripts/sync-mobile-web.mjs` copies
`index.csr.html` → `index.html` after syncing the rest of the build output.

### Gotcha: `cap add` before `cap sync`

`npx cap sync` **only copies web assets** — it does **not** add platforms. You
must run `npx cap add android` and `npx cap add ios` **first** (this also wires
the `@capacitor/camera` plugin into both native projects), then `npx cap sync`
syncs the web assets to both.

## Commands

All commands run from the repo root (`microfrontend/`) via Nx, or from
`apps/mobile/` via `npx cap`.

| Command | What it does |
| --- | --- |
| `npx nx run mobile:build-web` | Builds the shell, syncs to `web/`, runs `cap sync`. |
| `npx nx run mobile:sync` | Runs `npx cap sync` (web assets → native projects). |
| `npx nx run mobile:build-android` | `npx cap build android` (needs Android SDK + JDK). |
| `npx nx run mobile:build-ios` | `npx cap build ios` (needs Xcode, macOS only). |
| `npx nx run mobile:open-android` | Opens the Android project in Android Studio. |
| `npx nx run mobile:open-ios` | Opens the iOS project in Xcode. |

### Typical flow

```bash
# 1. Build the shell + sync web assets + cap sync (one command)
npx nx run mobile:build-web

# 2. Build the native app (Android)
npx nx run mobile:build-android
#    → APK under apps/mobile/android/app/build/outputs/apk/debug/

# 3. Or open in Android Studio and Run on an emulator
npx nx run mobile:open-android
```

## Native plugins & the bridge adapter

Native capabilities are accessed **only** through `@shared/bridge` (see
`libs/shared/bridge/README.md`). The catalog MF's "scan product" demo calls
`getBridgeAdapter().scanProduct()`, which:

- **Native:** uses `@capacitor/camera` (loaded on demand via dynamic import).
- **Browser:** falls back to `getUserMedia` + a canvas snapshot.

The `@capacitor/camera` plugin is declared in `apps/mobile/package.json` and
wired into both native projects by `cap add`. It is **not** bundled into the
web build (the adapter loads it dynamically only when native).

## WSL / Windows-host note (Android build)

`cap sync` is pure JS and works anywhere (including WSL). **`cap build android`
requires the Android SDK + JDK + a runnable Gradle**, which are **Windows-side**
in this environment:

- **WSL has no Android SDK / Java / Gradle.** The Windows host has them:
  - Android SDK: `C:\Users\Gaming\AppData\Local\Android\Sdk`
    (build-tools 36.0.0, platform android-37.0)
  - JDK 26: `C:\Program Files\Java\jdk-26.0.2.1`
  - Android Studio (JBR): `C:\Program Files\Android\Android Studio`
- **A Linux (WSL) Gradle process cannot execute the Windows `java.exe`** (a PE
  binary), so `cap build android` **cannot run from WSL** even with
  `JAVA_HOME`/`ANDROID_HOME` pointed at the Windows paths.

**Build path (Windows host):**

```powershell
# From Windows PowerShell, in the repo root (microfrontend\):
npx nx run mobile:build-android
# or
npx nx run mobile:open-android   # → Android Studio → Run (emulator on the host)
```

The Android emulator runs on the **Windows host**, not in WSL.

## Verification (Phase 5.4)

- `cap sync` — **verified ok** (web assets → `android/app/src/main/assets/public`
  + `ios/App/App/public`, `index.html` present).
- `cap build android` — **attempted from WSL**; Gradle wrapper runs but cannot
  execute the Windows `java.exe` → **Windows-host-only** (see above). Build and
  run on the emulator from the Windows host.
